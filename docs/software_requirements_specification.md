## 2. 软件功能需求详细规格 (Functional Specifications)

### 2.1 用户认证与权限控制子系统 (SWR-USR)

#### SWR-USR-001: 角色与按钮级权限控制软件规格 (无权限直接关闭)
* **功能描述**：软件必须实现基于 RBAC 的前端菜单隐匿、按钮级 DOM 物理移除与后端 API 路由双重拦截。根据工厂实际运维架构精简，**系统不设且不需要“车间主管 (Supervisor)”角色**，内置三大标准角色：`ADMIN`、`ENGINEER`、`TECHNICIAN`。
* **软件输入**：用户登录成功后获取的 `role_code: ['ADMIN' | 'ENGINEER' | 'TECHNICIAN']` 权限标识。
* **业务逻辑与实现规则**：
  * **侧边栏菜单级收敛**：在导航组件中通过 `v-if="authStore.isAdmin"` 严格受控，非 `ADMIN` 角色（`ENGINEER`、`TECHNICIAN`）的侧边栏完全不渲染“用户管理”和“系统设置”入口。
  * **前端全局权限指令 `v-permission`**：前端全局定义并注册 `v-permission="['ADMIN', 'ENGINEER']"` 指令。在元素挂载（`mounted`）生命周期中判定，若当前用户的 `role_code` 不在允许列表中，**直接调用 `el.parentNode?.removeChild(el)` 从 DOM 树中物理移除该节点**。
  * **受控按钮范围**：包括“录入设备信息”、“导出Excel”、“删除”、“编制维护计划”、“升级版本快照”、“编制实操新课程”、“抢单认领”、“维修复盘提交”等。
  * **技术员接单后权限开放**：技术员认领现场维护工单后，界面开放**工单信息编辑**与**现场工作完成证据图片上传**组件。
  * **后端双重拦截保障**：后端在每个受限 API 路由挂载 `Depends(require_role(...))` 依赖注入。非法调用时抛出业务异常，返回错误码 `10003: PERMISSION_DENIED`。
* **输出结果**：未授权角色登录后，无权限的菜单和按钮全部自动关闭/隐藏；技术员按规范接单编辑并上传凭据。

#### SWR-USR-002: 全局设备协同与免工种数据隔离机制
* **功能描述**：根据工厂实际敏捷协同需要，**彻底取消原责任工种 (电气/机械/自动化) 对设备与工单的数据隔离限制**。
* **业务逻辑**：
  * 系统创建新账号时**无需强制选择责任工种，无需执行工种数据隔离**。
  * 移除原持久层 `WHERE equipments.work_type = :user_work_type` 过滤约束，工程师与技术员可全局协同查看、巡检与维护全厂所有设备。
* **验收标准**：技术员可跨设备类别查看工单并协同执行维护，系统无工种壁垒阻碍。

#### SWR-USR-003: 账号全生命周期管理与软禁用/软删除
* **功能描述**：软件实现账户的新增、编辑、启禁用与安全软删除全流程闭环，禁止物理级硬删除。创建账号表单**不设车间主管角色，不设责任工种隔离项**。
* **输入校验**：
  * `username`：3~32位字符，仅支持字母、数字及下划线。
  * `employee_no`：唯一工号，格式校验 `EMP-[A-Z0-9]{4,8}` 或标准工号。
  * `email`：符合 RFC 5322 邮箱格式标准。
  * `role_code`：限定为 `['ADMIN', 'ENGINEER', 'TECHNICIAN']`。
* **软件处理**：
  * 提供 `PUT /api/v1/users/{id}` 支持管理员修改用户信息与启用/禁用状态（`is_active`）。
  * 提供 `DELETE /api/v1/users/{id}` 实现账号安全软删除（`is_deleted = TRUE`），保留历史数据审计关联。
  * 登录接口判定若 `is_active == FALSE` 或 `is_deleted == TRUE`，返回错误码 `10002: ACCOUNT_DISABLED`。

#### SWR-USR-004: 密码安全与强阻断改密控制
* **功能描述**：实现前端密码强度校验与强制改密的前后端双重防穿透阻断。
* **密码规则**：长度 $\ge 8$ 位，必须同时包含大写字母、小写字母、数字及特殊符号。
* **双重阻断实现**：
  * 后端：生成 JWT Token 时注入 `"fcp": true`。全局中间件拦截非改密接口，返回 `10008: FORCE_PASSWORD_CHANGE_REQUIRED`。
  * 前端：Vue Router 全局 `beforeEach` 守卫监测到 `fcp === true` 时，无条件跳转至 `/force-change-password`，隐藏主布局框架。

#### SWR-USR-005: 邮箱密码找回与一次性时效 Token
* **功能描述**：通过异步邮件发送重置链接，链接携带安全随机密钥。
* **处理机制**：生成 UUID 作为 Token，存入 Redis：`key="pwd_reset:" + token`, `value=user_id`, `ex=900`（15分钟）。重置密码成功后立即调用 `redis.delete()`，保证单次有效。

#### SWR-USR-006: 登录防护与生产单班次 8 小时长效会话
* **功能描述**：抵御暴力破解，并保障车间单班次 8 小时免重登连续作业。
* **软件处理**：
  * 密码错误时，Redis 中对应账户失败计数自增 1，TTL=900秒。达到 5 次将账户锁定，返回错误码 `10001: ACCOUNT_LOCKED` 并返回剩余秒数。
  * 后端 JWT Token 签名有效时长设定为 **480 分钟（8小时）**，覆盖标准工作班次，杜绝现场维护单填写与工单处理中途凭据过期踢出。
  * 前端监听全局鼠标移动、按键与触摸事件。若连续 30 分钟无事件触发，清除本地 Token 并主动安全登出。

#### SWR-USR-007: 全局操作人审计自动注入
* **功能描述**：ORM 实体监听器在执行 `INSERT` 与 `UPDATE` 时，自动从当前请求上下文提取 `current_user.id`，回填至 `created_by` 与 `updated_by`。

#### SWR-USR-008: 操作级权限细粒度校验
* **功能描述**：按“录入、编辑、删除、导出、查阅”五维进行代码级鉴权，杜绝任何纵向/横向越权漏洞。

### 2.2 设备信息与4级层级拓扑子系统 (SWR-DEV)

#### SWR-DEV-001: 4级层级拓扑树 (工厂 -> 部门 -> 系统 -> 设备信息)
* **功能描述**：实现工厂、部门、系统、设备信息四级固定树形拓扑结构。管理员具备统一录入、维护与调整工厂、部门、系统层级及挂载设备信息的全套权限。
* **层级模型规则**：
  * Level 1: 工厂 (Factory)
  * Level 2: 部门 (Department)
  * Level 3: 系统 (System)
  * Level 4: 设备信息 (Equipment Information)
* **防成环与深度校验**：新节点深度严格受限为 $1 \le \text{level\_depth} \le 3$（工厂、部门、系统），设备实体强制挂载在 Level 3 系统节点下。成环移动抛出 `20003: CYCLIC_HIERARCHY_DETECTED`。

#### SWR-DEV-002: 层级节点防孤儿删除校验
* **功能描述**：删除节点前，在同一事务中检测：
  1. 检测下级层级节点引用：`SELECT COUNT(1) FROM equipment_locations WHERE parent_id = :id AND is_deleted = false`
  2. 检测挂载设备信息引用：`SELECT COUNT(1) FROM equipments WHERE location_id = :id AND is_deleted = false`
  若任一项 $> 0$，抛出 `20001: CANNOT_DELETE_NODE_WITH_CHILDREN_OR_EQUIPMENT`。

#### SWR-DEV-003: 设备信息规范化录入与页面字段精简治理
* **功能描述**：建立标准化设备信息档案。录入设备信息表单全面剔除“设备类型”、“责任专业”与“维护倒计时周期”（维护周期统一由“设备维护 - 维护计划”按需制定并与实际运行工时挂钩，设备台账专注资产物理与参数信息）。设备编码唯一性自动校验、关联所属工厂/部门/系统节点、额定电压与设备参数信息录入。
* **表单校验**：设备编码唯一性校验，设备编码、设备名称、规格型号、所属系统节点为前端必填项。

#### SWR-DEV-004: 设备参数信息自由文本录入与灵活展示 (废除死板11类Schema强校验)
* **功能描述**：工业设备种类繁多、现场技术参数规格差异大，废除原死板的 11 类设备 Schema 强校验规则，改由「设备参数信息」自由文本格式 (`params_text`) 录入与存储。
* **业务逻辑与交互**：
  * **自由多行录入**：支持技术人员以纯文本/键值对/工况说明等任意自由格式输入设备技术参数、控制协议、电气性能、风压量程等。
  * **免强校验阻断**：不再对 IP、转速等实行死板的正规表达与数值范围强拦截，最大程度保障工业现场的录入效率与兼容性。
  * **明细格式化回显**：设备列表中提供“查看参数信息”按钮，弹窗以等宽格式化文本清晰展示设备全部技术参数。

#### SWR-DEV-005: 设备有限状态机跃迁引擎
* **功能描述**：软件通过状态机服务严格控制设备状态变更：`RUNNING` $\leftrightarrow$ `MAINTENANCE_PENDING` $\leftrightarrow$ `FAULTY` $\leftrightarrow$ `SHUTDOWN` $\rightarrow$ `SCRAPPED`。非法跃迁抛出 `20005: INVALID_STATUS_TRANSITION`。

#### SWR-DEV-006: 工业级标签化附件与解耦存储 (反省改进)
* **功能描述**：实现附件与业务表单的直传解耦。上传文件时在 `equipment_files` 标记 `is_linked = FALSE`。业务表单保存时更新为 `TRUE`。未关联的孤儿文件由后台定时任务清理。标签类别新增“工作证据图片”分类。

#### SWR-DEV-007: 设备信息多维组合复合查询
* **功能描述**：支持前端构建复合查询过滤对象，后端通过动态 SQL 构建器（支持工厂/部门/系统层级联动、设备类型、运行状态）实现高效索引覆盖检索，分页拉取。

#### SWR-DEV-008: 设备全生命周期电子履历时间轴组件
* **功能描述**：聚合目标设备的历次现场维护记录、现场图片证据、故障事件、更换备件与停机时长，按倒序渲染为交互式时间线。

#### SWR-DEV-009: Excel 导入解析器与数据清洗预览
* **功能描述**：前端提供模板下载，后端采用流式读取 Excel，支持批量录入工厂/部门/系统及设备信息，逐行执行 Schema 校验，返回通过行数与错误单元格坐标，预览确认后再事务性写入。

### 2.3 设备维护与现场维护单子系统 (SWR-MNT)

#### SWR-MNT-001: 维护计划编制 (倒计时周期最小为小时)
* **功能描述**：支持图文混排的维护操作说明。**编制维护计划内部倒计时周期单位最小为小时 (hours)**（`interval_hours: int`），支持设置 2h、4h、12h、24h、72h 等灵活的小时级维护频次。

#### SWR-MNT-002: 设备维护内容清单与标准配图渲染
* **功能描述**：维护计划内支持定义结构化的“**设备维护内容**”清单（取代原“SOP 巡检规范清单”）。支持动态增删维护项，每个条目支持关联标准参考照片与判定要求，方便移动端比对。

#### SWR-MNT-003: 维护计划版本快照固化机制
* **功能描述**：当维护计划被编辑保存时，计划版本自增（如 V1.0 $\rightarrow$ V1.1）。已派发的工单及历史维护记录，永久保存其生成时引用的版本号与维护内容快照，绝不变更。

#### SWR-MNT-004: 小时级动态倒计时批处理调度 (反省改进)
* **功能描述**：后台守护调度器以**小时**为最小单位实时更新设备倒计时状态。软件采用**游标分批拉取 (Cursor Chunking, size=100)**，单台设备更新失败进行异常捕获并记录审计日志，绝不中断批量处理流程。

#### SWR-MNT-005: 维护到期多时间点邮件防重调度
* **功能描述**：支持管理员灵活配置提前通知节点（按小时级定义，如提前 72h、24h、2h 或到期时刻）。发信前必须执行幂等检查：`SELECT 1 FROM maintenance_notify_logs WHERE ...`，已发信则直接跳过，杜绝重复投递。

#### SWR-MNT-006: 维护工单派发与接单流转
* **功能描述**：设备倒计时到期时，系统自动生成 `MAINTENANCE_PENDING` 任务工单，推送至技术员待办池。技术员接单后，工单状态置为进行中，并开放编辑与工作凭证上传功能。

#### SWR-MNT-007: 现场维护单执行、编辑与工作完成证据图片上传
* **功能描述**：现场巡检打卡统一升级为“**现场维护单**”。
* **核心业务逻辑**：
  * **接单权限增强**：**技术员接了工单后，具备编辑工单信息功能**，包括填报维护作业过程、记录实测参数、备件耗材等。
  * **工作完成证据图片上传**：技术员必须能够直接拍照或上传现场图片作为工作完成的严肃证据链（`evidence_file_id` 与附件关联），未上传凭据可配置为阻断提交。
  * **设备维护内容逐项判定**：技术员对维护清单逐项单选（正常/异常），若判定异常则强制填报异常现象描述并附上异常现场照片。

#### SWR-MNT-008: 现场维护单异常单事务联锁生成故障单
* **功能描述**：`POST /api/v1/maintenance/inspections/submit` 聚合接口在**单一本地数据库事务**内完成：
  1. 写入 `inspection_records`（现场维护单总表）；
  2. 写入 `inspection_record_details`（维护内容明细与工作证据）；
  3. 若包含异常项，自动构造 `fault_records`（来源为 `INSPECTION_AUTO`，状态为 `OPEN`）；
  4. 回填 `fault_id` 至异常维护明细；
  5. 跃迁目标设备状态为 `FAULTY`；
  6. 事务成功后触发异步邮件通知事件。

#### SWR-MNT-009: 维护超时报警与持续催办
* **功能描述**：超过截止时间未完成现场维护单的任务，状态自动置为 `OVERDUE`，每日早上 08:00 投递催办邮件至管理员与责任工程师。

#### SWR-MNT-010: 维护按时完成率多维度统计分析
* **功能描述**：后台聚合服务按工厂/部门/系统、月份统计按时完成率指标，生成符合 ECharts 格式的序列化数据供前端数据平台渲染。

#### SWR-MNT-011: 现场维护单明细全量报表 Excel 导出
* **功能描述**：支持将选定时间区间内的现场维护单明细（包含逐项检查结果、技术员工作记录与证据图片链接）导出为标准 Excel 报表。

#### SWR-MNT-012: 实际运行工时驱动的预测性维保与动态倒计时通知 (Meter-Based Maintenance)
* **功能描述**：实现基于机台实际运行工时累加（非固定 7×24 小时自然日历）的预测性维保与预警引擎。支持现场操作员每日/每班次填报机台运行小时数，系统在满足预警阈值时自动发送邮件通知并派发维护工单，维护完成后自动重置工时计数器。
* **软件输入**：
  * **维护计划配置**：`trigger_mode: ['CALENDAR' | 'OPERATING_HOURS']`，`interval_hours`（目标维保周期，如 720h），`advance_warning_hours`（提前预警小时数，如 48h）。
  * **每日工时填报**：`equipment_id`、`log_date`、`duration_hours`（浮点数，步进 0.5h，单日上限 24.0h）、`proof_image_id`（可选仪表照片凭据）、`remarks`。
* **业务逻辑与实现规则**：
  1. **防作弊与单日工时守恒校验**：后端强校验同一设备在同一自然日累计填报时长不得超过 24.0 小时，且每次填报必须大于 0。
  2. **工时原子累加与快照记录**：每次填报在独立本地事务中执行原子累加 `equipment.current_operating_hours += duration_hours`，并向 `equipment_operating_logs` 表插入快照流水。
  3. **预警线判定与邮件通知**：计算剩余运行工时 `remaining_hours = interval_hours - current_operating_hours`：
     * 若 `remaining_hours <= advance_warning_hours` 且本周期未发送过预警邮件，系统调用 SMTP 服务向设备责任工程师及班组推送预警邮件，并生成 `PENDING` 维护工单。
     * 若 `remaining_hours <= 0`，设备运行状态自动跃迁为 `MAINTENANCE_PENDING`。
  4. **完工闭环与计数重置**：技术员在【现场维护单】打卡完成该工单并提交工作证据后，系统自动将设备的 `current_operating_hours` 清零重置，开启下一个工时维保周期。
* **验收标准**：
  * 操作员在【现场维护单-运行工时填报】中 3 秒内完成打卡，进度条实时更新；
  * 到达 672 小时（距 720h 差 48h）时，成功发送预警邮件并自动生成待办工单；
  * 维保完成打卡后，累计工时计数自动归零，下一个 720 小时周期重新开始。

### 2.4 故障时效与闭环流转子系统 (SWR-FLT)

#### SWR-FLT-001: 故障双来源归一化接入
* **功能描述**：无论是由巡检异常自动联锁生成，还是由车间技术员主动填报，均进入统一的故障流转池，并以 `source_type` 明确标识。

#### SWR-FLT-002: 故障核心要素标准化录入
* **功能描述**：必填故障标题、故障描述、系统分类、部件位置、严重等级（严重/一般/轻微）、关联设备及现场证据照片。

#### SWR-FLT-003: 故障录入实时智能排查推荐 (前端与引擎协同)
* **功能描述**：
  * 前端：技术员在“故障描述”文本框键入时，设置 300ms 防抖函数 (`debounce`)，异步调用 `/api/v1/faults/recommend-similar`。
  * 后端：优先匹配当前设备型号与系统，提取候选集，计算分词加权得分，过滤得分 $\ge 60\%$ 的前 3 条结果返回。
  * 缓存：若查询无结果，向 Redis 写入空值占位（TTL=60s），防止频繁击穿数据库。

#### SWR-FLT-004: 故障状态流转控制
* **功能描述**：状态按 `OPEN` $\rightarrow$ `IN_PROGRESS` $\rightarrow$ `RESOLVED_PENDING_REVIEW` / `RESOLVED` $\rightarrow$ `CLOSED` 推进，支持打回重新流转。

#### SWR-FLT-005: 工程师并发接单状态乐观锁 (反省改进)
* **功能描述**：工程师认领工单时，执行带前置状态条件的原子更新：
  `UPDATE fault_records SET status = 'IN_PROGRESS', ... WHERE id = :id AND status = 'OPEN'`
  若受影响行数等于 0，则直接抛出业务异常 `40003: FAULT_ALREADY_CLAIMED`，并在前端提示“该故障单已被其他工程师认领”。

#### SWR-FLT-006: 维修复盘根因与处理步骤强制填报
* **功能描述**：在调用解决工单接口时，`root_cause` 与 `solution_steps` 字段实施强校验（字符长度均不得低于 10 个字符），未满足直接拦截。

#### SWR-FLT-007: 标定典型故障案例与知识打标
* **功能描述**：工程师或管理员可在解决后勾选 `is_featured_case = TRUE`，打上专属金标，并在知识库中置顶展示。

#### SWR-FLT-008: SLA 响应与解决时效自动轮询监控
* **功能描述**：后台定时任务每 5 分钟扫描未闭环工单，计算响应超时与解决超时。严重故障响应超 30 分钟未接单，自动标记 `is_sla_response_breached = TRUE` 并发送升级催办邮件。

#### SWR-FLT-009: 故障明细及复盘方案导出
* **功能描述**：支持导出包含故障现象、根本原因、解决方案及耗时明细的 Excel 汇总表。

#### SWR-TRN-005: 员工技能全生命周期电子档案卡
