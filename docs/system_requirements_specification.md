## 1. 需求编号规则说明

为确保需求在系统架构设计、数据库建模、API接口契约、前端视图及测试用例中具备 **100% 可追溯性 (Traceability)**，本系统所有需求采用统一的结构化编号编码：

$$\text{REQ} - [\text{模块代码}] - [\text{三位序号}]$$

| 模块代码 | 对应业务领域 | 编号范围 | 覆盖范围描述 |
|:---|:---|:---|:---|
| **USR** | 用户与权限管理 (User & Permission) | REQ-USR-001 ~ 008 | 三大内置角色 (管理员/工程师/技术员)、免工种数据隔离、账号生命周期、密码与安全策略、操作审计标记 |
| **DEV** | 设备信息 (Equipment Information) | REQ-DEV-001 ~ 009 | 4级拓扑树 (工厂/部门/系统/设备)、11类设备参数建模、状态机、标签化附件、维修履历、导入导出 |
| **MNT** | 设备维护 (Equipment Maintenance) | REQ-MNT-001 ~ 011 | 维护计划与SOP、设备维护内容清单、倒计时(最小单位小时)、现场维护单、技术员接单编辑与图片凭证、异常联锁、完成率统计 |
| **FLT** | 故障管理与时效 (Fault & SLA) | REQ-FLT-001 ~ 009 | 双源报修、要素录入、智能排查推荐、状态流转、SLA分级时效、根因沉淀、典型案例 |

| **TRN** | 培训管理与技能档案 (Training Management) | REQ-TRN-001 ~ 005 | 课程编制、故障案例教材挂接、培训组织签到、考核评定与复训、个人技能档案 |
| **DSH** | 数据平台 (Data Platform / FCM平台) | REQ-DSH-001 ~ 004 | FCM设备运维管理平台大盘、统计卡片、三角色差异化待办、趋势图表、全局快捷入口 |
| **SYS** | 系统支撑与配置 (System & Infrastructure) | REQ-SYS-001 ~ 006 | SMTP邮件配置、通知接收组、调度触发引擎、Excel导入导出底座、180天审计日志、文件存储 |
| **NFR** | 非功能性需求 (Non-Functional Requirements) | REQ-NFR-001 ~ 005 | 安全防御、接口与首屏性能、数据规模容量、数据可靠性与软删除、终端浏览器兼容 |

## 2. 详细功能需求规格 (Functional Requirements)

### 2.1 用户与权限管理 (REQ-USR)

#### REQ-USR-001: 三层内置角色与无权限功能直接关闭规格
* **需求描述**：系统必须内置支持三种标准工业角色：**系统管理员 (Admin)**、**维修工程师 (Engineer)**、**维保技术员 (Technician)**。根据工厂实际运维结构精简，**系统不设且不需要“车间主管 (Supervisor)”角色**。
* **角色职能划分**：
  * **管理员 (Admin)**：拥有系统最高权限，具备用户创建/编辑/软删除、工厂/部门/系统层级拓扑录入与维护、系统底层设置（SMTP发信、服务端口、防篡改审计）、全局数据查阅与维护计划编制权限。
  * **工程师 (Engineer)**：具备设备信息增删改查、维护计划编制与版本快照升级、故障工单并发认领与复盘提交、验收归档、编制技能实训课程、精编知识库与标定典型案例权限。
  * **技术员 (Technician)**：具备接收与执行现场维护单、**接单后编辑维护工单内容与上传现场工作完成证据图片**、突发故障快速报修、查询排故知识库、参与实训考评档案权限。**严禁**具备系统配置、账号管理与未授权删除权限。
* **无权限功能直接关闭与物理移除规则**：
  * **侧边栏菜单收敛**：对于当前登录角色无权访问的模块菜单（如非管理员访问“用户与班组管理”、“系统设置与审计”），在侧边栏导航中**直接隐藏**，不渲染任何入口。
  * **路由级强阻断**：非授权角色直接通过浏览器地址栏敲击受限 URL（如 `/users`、`/system`）时，全局路由守卫直接拦截并重定向至 403 页面，严禁请求后端数据接口。
  * **按钮级 DOM 物理移除**：对于当前角色无权执行的操作按钮（如“录入设备”、“导出Excel”、“删除”、“编制维护计划”、“升级版本”、“编制实操新课程”、“抢单认领”、“维修复盘提交”等），前端界面通过统一权限指令将节点直接从 DOM 树中物理移除，**彻底关闭操作入口，严禁出现“按钮可见、点击后弹出权限不足错误提示”的不良交互体验**。
* **验收标准**：以 `TECHNICIAN` 账号登录系统后，左侧菜单完全不展示“用户与班组管理”和“系统设置与审计”，界面中无权操作的按钮彻底物理移除，用户在整个使用过程中 100% 不会触发“权限不足：当前角色【XXX】无权访问此功能”的报错。

#### REQ-USR-002: 全局设备协同与免工种数据隔离机制
* **需求描述**：根据工厂实际敏捷协同需要，**彻底取消原责任工种 (电气/机械/自动化) 对设备与工单的数据隔离限制**。
* **规则细则**：
  * **免数据隔离**：创建账号时**不需要“责任工种 (数据隔离)”**，各级工程师与技术员均面向全厂或所属工厂、部门、系统的所有设备具备查看、协同巡检与维护权限。
  * **打破工种壁垒**：机电一体化与自动化设备维护由团队全局协同，避免因单一工种隔离导致现场紧急维保或抢修时“跨工种不可见”而延误抢修。
* **验收标准**：任意技术员登录后，设备列表及维护工单池中可查看所有类型的设备与任务，无需切换工种即可进行协同处理。

#### REQ-USR-003: 账号全生命周期管理与安全闭环
* **需求描述**：管理员在“用户与班组管理”中统一创建新账号、编辑、启禁用与软删除系统账户。系统创建新账号表单中**不设“车间主管”角色选项，不设“责任工种 (数据隔离)”选择项**。
* **输入字段**：用户名（唯一）、初始密码、真实姓名、工号（唯一）、电子邮箱（用于通知重置）、手机号、所属角色（管理员 / 工程师 / 技术员）。
* **生命周期策略**：
  * 账户创建后初始状态为 Active，支持管理员动态修改人员姓名、工号、邮箱及角色。
  * 员工离职或调岗时，管理员可执行禁用（`is_active = FALSE`）或软删除（`is_deleted = TRUE`），**禁止物理硬删除**账户。
* **验收标准**：创建新账号弹窗中仅提供管理员、工程师、技术员三种角色，无工种选择框；被禁用或软删除的账户无法登录，但历史业务审计中修改人/创建人仍正常显示。

#### REQ-USR-004: 密码安全与过期轮换机制
* **需求描述**：系统实施严格的口令生命周期管理。
* **规则细则**：
  * 首次登录强制改密：新建用户首次登录时，系统必须强制弹出修改密码窗口，改密完成前阻断所有其他功能访问。
  * 复杂度要求：长度不少于 8 位，必须包含大小写字母、数字及特殊字符。
  * 90 天定期过期：密码有效期为 90 天，到期前 7 天登录触发提醒，逾期登录强制改密。
* **验收标准**：新创建账号在未修改默认密码时调用任意业务接口均返回必须先改密的特定错误码。

#### REQ-USR-005: 密码自助找回与重置
* **需求描述**：用户忘记密码时，可通过绑定的电子邮箱自助发起重置。
* **处理流程**：用户输入注册邮箱 -> 系统生成单次有效且有效期为 15 分钟的安全加密 Token -> 发送重置链接至用户邮箱 -> 用户点击链接输入新密码完成重置。
* **验收标准**：Token 一次性消费后立即失效，超过 15 分钟未操作自动失效。

#### REQ-USR-006: 登录防护与生产班次长效会话安全
* **需求描述**：防范暴力破解与保障车间单班次免重复登录作业。
* **规则细则**：
  * 密码加密：数据库中存储的密码必须使用高强度加盐哈希（bcrypt，cost >= 10），严禁明文存储。
  * 防暴破锁定：同一个用户名或客户端 IP 连续密码错误达到 5 次，自动锁定该账号 15 分钟，并在界面友好提示剩余锁定时间。
  * 生产班次会话时效：后端 JWT Access Token 签名有效期设定为 **480 分钟（8小时）**，完全覆盖离散制造工厂 8 小时单班次不间断作业需求，杜绝在工单录入或巡检中途因凭证超时意外退出。
  * 无操作超时登出：前端监听用户交互事件，若连续 30 分钟无键盘、鼠标及触摸动作，前端主动销毁本地缓存凭据并登出。
* **验收标准**：第 5 次密码错误后锁定 15 分钟；技术员在 8 小时工作班次内无需重复输入密码重新登录。

#### REQ-USR-007: 全局业务实体创建与修改人审计标记
* **需求描述**：系统的每一条业务数据记录（设备、分类、维护计划、巡检记录、故障单、知识库条目）必须具备操作人审计追溯能力。
* **规则细则**：
  * 数据库实体必须包含：created_by（创建人ID）、created_at（创建时间）、updated_by（最后修改人ID）、updated_at（最后修改时间）。
  * 业务前端详情页与列表页中，明确标注“录入人/最后修改人：[姓名] ([工号])”。
* **验收标准**：工程师 A 修改了设备参数，设备详情页能立刻显示“修改人：工程师A，修改时间：YYYY-MM-DD HH:mm:ss”。

#### REQ-USR-008: 操作级细粒度权限矩阵控制
* **需求描述**：系统按照“编辑、修改、删除、导出、录入”五大动作维度对三类内置角色进行权限矩阵控制。
* **三角色权限矩阵规格**：

| 操作动作 | 管理员 (Admin) | 工程师 (Engineer) | 技术员 (Technician) |
|:---|:---:|:---:|:---:|
| 录入 (Create) | 全局录入、用户开户、工厂/部门/系统层级录入 | 录入设备信息/维护计划/课程/知识 | 录入现场维护单/故障报修 |
| 编辑/修改 (Update) | 全局修改、用户状态、层级拓扑调整与系统配置 | 修改设备信息/维护计划版本升级/故障复盘 | **接单后编辑工单内容及上传现场工作完成证据图片** |
| 删除 (Delete) | 全局软删除（用户/设备/层级节点） | 设备信息软删除/维护计划草稿删除 | 无删除权限（按钮物理移除） |
| 导出 (Export) | 全量报表导出、数据平台导出 | 设备信息/工单/知识库导出 | 无导出权限（按钮物理移除） |
| 查阅 (Read) | 全局无限制查看 | 全局设备/维护计划/工单/知识库 | 权限内设备维护单及知识检索 |

### 2.2 设备管理 (REQ-DEV)

#### REQ-DEV-001: 4级层级拓扑树 (工厂 -> 部门 -> 系统 -> 设备信息)
### 2.2 设备信息 (REQ-DEV)

#### REQ-DEV-001: 车间层级拓扑树 (工厂 -> 部门 -> 系统 -> 设备信息)
* **需求描述**：车间层级拓扑树逻辑修改为由系统管理员统一录入与维护**工厂、部门、系统、设备信息**四级树形拓扑结构。
* **规则细则**：
  * **四级固定层级结构**：
    1. **第 1 级（工厂）**：顶级工业园区/制造工厂实体（如“总装制造一厂”）。
    2. **第 2 级（部门）**：厂区下属生产车间或职能部门（如“冲压车间”、“装配部门”）。
    3. **第 3 级（系统）**：部门内部运行的工艺系统或产线系统（如“输送传动系统”、“机器人焊接系统”、“空压动力系统”）。
    4. **第 4 级（设备信息）**：挂载归属于特定系统下的具体物理设备实体。
  * **管理员维护权限**：管理员可动态录入、编辑、重命名、调整工厂、部门、系统节点，并在系统节点下挂载录入设备信息。
  * **层级挂载约束**：设备信息必须且仅能挂载在第 3 级“系统”节点之下，工厂与部门作为上层组织聚合单元。
* **验收标准**：管理员在前端层级拓扑界面中可顺畅录入“工厂 -> 部门 -> 系统”，并在选定系统后一键录入设备信息，层级关系清晰呈现。

#### REQ-DEV-002: 层级节点防孤儿校验与维护
* **需求描述**：对工厂、部门、系统节点执行删除操作时，实施严密的层级完整性级联防孤儿保护。
* **规则细则**：
  * 若工厂下存在部门，禁止直接删除工厂。
  * 若部门下存在系统，禁止直接删除部门。
  * 若系统下已录入挂载有设备信息（即使设备处于停机或报废状态），禁止删除该系统节点。
* **验收标准**：删除存在下级关联的节点时，接口返回 400 Bad Request，明确提示阻断原因。

#### REQ-DEV-003: 设备信息通用档案核心字段建模
* **需求描述**：系统管理制造业 11 类设备，统一建立标准化设备信息档案。
* **核心字段清单**：
  * 设备编码（唯一识别码，如 DEV-PLC-2026-001）
  * 设备名称（如 主进料输送机）
  * 设备类型（传感器、PLC、风机、电机、变频器、HMI、伺服驱动、液压、气动、输送、其他）
  * 品牌/制造商、规格型号、出厂序列号 (SN)
  * 所属层级拓扑（关联工厂、部门、系统节点）
  * 购置日期、启用日期、使用年限、保修截止日期
  * 维护周期基线（支持按小时或天配置）
  * 负责工程师（指定具体负责人）
  * 当前运行状态（正常/待维护/故障/停机/报废）
* **验收标准**：设备通用信息校验合法后持久化落库，支持条形码/二维码生成与关联。

#### REQ-DEV-004: 11类设备差异化专有参数建模
* **需求描述**：各类设备工作原理差异显著，必须支持针对设备类型的扩展参数模型。
* **参数规格清单**：
  1. **传感器**：测量类型（温度/压力/光电/位移等）、测量量程、输出信号（4-20mA, 0-10V, 开关量）、综合精度等级。
  2. **PLC**：CPU 型号、IP 地址、子网掩码、通信协议（Profinet, Modbus TCP等）、DI/DO/AI/AO 点数配置、固件版本。
  3. **风机**：额定风量 (m3/h)、全压 (Pa)、轴功率 (kW)、额定转速 (rpm)、驱动方式（直联/皮带/联轴器）。
  4. **电机**：额定功率 (kW)、额定电压 (V)、额定电流 (A)、额定转速 (rpm)、绝缘等级（如 F 级）、防护等级（如 IP55/IP65）。
  5. **变频器**：适配功率、额定输入电压、额定输出电流、控制方式（V/F、矢量、转矩控制）、总线接口（Modbus/CanOpen等）。
  6. **HMI (触摸屏)**：屏幕尺寸（英寸）、分辨率、操作系统/运行时版本、网口与串口通讯通道配置。
  7. **伺服驱动器**：额定功率、额定转矩、峰值转矩、编码器类型（绝对值/增量式/旋变）、控制总线协议。
  8. **液压元件**：额定工作压力 (MPa)、系统额定流量 (L/min)、工作介质牌号（如 46号抗磨液压油）。
  9. **气动元件**：工作气压范围 (MPa)、工作流量 (L/min)、过滤精度、气缸缸径与行程。
  10. **输送设备**：线体运行线速度 (m/min)、皮带/链条有效宽度 (mm)、最大设计载重 (kg)。
  11. **其他自定义设备**：动态键值对 (Key-Value) 自定义技术参数表。
* **验收标准**：录入 PLC 设备时，表单动态渲染 PLC 专有字段（如 IP 地址合法性校验），保存后能正确持久化与查询。

#### REQ-DEV-005: 设备生命周期有限状态机 (FSM)
* **需求描述**：设备状态必须严格受状态机流转控制，保证系统数据状态一致。
* **状态机定义**：
  * **正常 (Running)**：基础常态。
  * **待维护 (Maintenance Pending)**：系统判定维护倒计时到期时，自动跃迁为该状态；现场维护单提交后自动恢复为正常。
  * **故障 (Faulty)**：现场维护单提交异常项或现场主动报修时，系统自动跃迁为该状态；维修闭环确认后方可恢复为正常。
  * **停机 (Shutdown)**：工程师或管理员手动切换（计划内保养或季节性停产）；手动恢复运行后回到正常。
  * **报废 (Scrapped)**：管理员操作，不可逆终态。报废后不能生成新维护任务与报修单，历史数据永久只读归档。
* **验收标准**：处于“报废”状态的设备，维护计划停止对其调度，且在待办列表中被自动过滤剔除。

#### REQ-DEV-006: 多媒体与多格式标签化附件管理
* **需求描述**：为现场工程师与技术员提供无纸化、移动化的图纸与程序查阅能力。
* **规格要求**：
  * 支持标签分类：设备照片、铭牌照片、使用说明书、电气原理图、PLC备份程序、工作证据图片、其他资料。
  * 支持格式：图片（JPEG, PNG, WEBP）、文档（PDF, DOC, DOCX）、代码/程序压缩包（ZIP, RAR, 7Z）。
  * 大小限制：单张图片不超过 10MB；单个文档或程序包不超过 50MB。
* **验收标准**：上传电气图纸 PDF 后，可直接在浏览器中预览或下载查看，上传程序包带有文件哈希校验防损坏。

#### REQ-DEV-007: 设备信息多维度综合检索
* **需求描述**：支持海量设备信息的高效检索与定位。
* **检索维度**：支持设备编码、设备名称模糊检索；支持按设备类型、工厂/部门/系统层级联动、运行状态、负责工程师组合过滤。
* **验收标准**：在 1000 台设备规模下，输入“风机”或勾选“总装车间 + 传动系统 + 待维护”，检索结果在 500ms 内返回并分页呈现。

#### REQ-DEV-008: 设备维修履历时间线 (Timeline)
* **需求描述**：每台设备详情页必须具备专属的“全生命周期电子病历”。
* **展示内容**：
  * 按时间倒序呈现历史维护记录、现场维护单凭证、故障事件、更换备件清单、维修处理人、恢复运行时间。
  * 自动统计：累计故障次数、累计停机时长 (MTBF / MTTR 关键基础数据)、高频故障部件与系统。
* **验收标准**：点击任意设备“维修履历”，能直观查看历次故障与维护的处理方案、工作证据与时间跨度。

#### REQ-DEV-009: 设备信息与层级拓扑 Excel 批量导入与导出
* **需求描述**：支持工厂初期快速建立设备信息库、层级拓扑与定期数据备份。
* **处理流程**：下载标准 Excel 导入模板 -> 填写工厂/部门/系统及设备参数 -> 上传解析校验 -> 校验异常时返回具体单元格错误清单 -> 校验通过后弹窗预览 -> 确认批量落库。
* **导出支持**：支持按当前筛选条件一键导出符合格式的 Excel 文件。
* **验收标准**：导入包含 200 台设备的合法 Excel，10 秒内全部完成入库并挂载到指定系统节点。

### 2.3 设备维护 (REQ-MNT)

#### REQ-MNT-001: 维护计划编制与图文说明
* **需求描述**：工程师为设备制定规范化的定期维护作业规范。
* **要素清单**：
  * 维护计划名称、维护类型（日常维护/定期保养/专项大修）。
  * 关联目标设备列表。
  * **倒计时周期频率**：**编制维护计划内部倒计时周期单位最小为小时 (hours)**，可灵活设定为 2 小时、4 小时、12 小时、24 小时（1天）、168 小时（1周）等。
  * 生效起始日期时间。
  * 维护操作图文操作说明（富文本与指导图片）。
* **验收标准**：计划生效后，系统自动以小时为最小基准单位排定倒计时日程。

#### REQ-MNT-002: 设备维护内容清单建模 (原逐项判定清单)
* **需求描述**：维护计划内部支持定义结构化的“**设备维护内容**”清单（取代原“SOP 巡检规范清单”），规范技术员作业步骤。
* **清单要素**：
  * 维护内容名称（如“检查电机轴承润滑情况”、“PLC 通信指示灯状态检查”）。
  * 维护要求与判定基准。
  * 标准参考图示（如标准油位线实物照片）。
  * 是否强制要求提供现场工作证据。
* **验收标准**：现场维护单界面中，每一项维护内容均清晰列出要求，技术员逐项判定并执行。

#### REQ-MNT-003: 维护计划版本迭代与快照机制
* **需求描述**：维护标准与要求会随着工厂改进不断升级。
* **规则细则**：
  * 工程师修改维护计划（如修改维护内容或周期小时数）时，系统自动升级版本号（如 V1.0 -> V1.1）。
  * 历史已生成的维护工单与已完成的现场维护单，**永久绑定当时执行的历史版本快照**，绝不随后续计划的修改而改变历史真实数据。
* **验收标准**：回溯历史维护记录，其显示的设备维护内容清单与判定标准精确呈现当时版本。

#### REQ-MNT-004: 维护周期小时级动态倒计时与下次节点推算
* **需求描述**：系统以**小时 (hours)** 为最小单位动态展示离下次维护的剩余时间。
* **推算规则**：
  * 首次维护时间：根据计划生效时间加上设置的周期小时数计算。
  * 后续维护时间：当次现场维护单提交完成时，系统以当前完成提交时间加上计划周期小时数，动态推算并更新下一次维护截止时间。
* **验收标准**：数据平台与设备维护列表中实时呈现“距下次维护剩余 X 小时”或“已超时 Y 小时”。

#### REQ-MNT-005: 多节点维护到期邮件提醒与灵活配置
* **需求描述**：支持管理员灵活配置提前通知时间节点（按小时或天换算），防止维护逾期。
* **规则细则**：
  * 管理员可在后台配置通知时间节点（例如提前 72 小时、24 小时、2 小时及到期时刻）。
  * 每个时间节点均支持独立开启/禁用开关。
  * 支持配置通知接收组及关联计划的专职责任人。
* **验收标准**：当设备距离维护到期达到预设节点时，后台调度系统准时向责任工程师及技术员邮箱投递提醒邮件。

#### REQ-MNT-006: 维护工单派发与接单流转
* **需求描述**：维护到期或生成维护单时，系统向对应技术员工作台派发“设备维护任务工单”。
* **接单机制**：技术员可接收工单认领执行。**接单后，工单进入进行中状态，技术员获得工单编辑与现场凭据上传权限**。
* **验收标准**：技术员接单后，工单状态更新，且界面即刻展现工单内容编辑表单与图片上传组件。

#### REQ-MNT-007: 现场维护单执行、编辑与工作完成证据上传
* **需求描述**：现场维护与巡检打卡统一升级为“**现场维护单**”。技术员接了工单后，必须具备编辑维护工单内容以及上传现场图片功能，作为工作完成的严肃证据链。
* **交互规则**：
  * **设备维护内容逐项判定**：技术员对维护清单中的各项进行逐项核验（正常/异常）。
  * **工单内容编辑**：技术员可编辑维护过程描述、更换零部件记录、参数实测数值、耗时等。
  * **工作完成证据图片上传**：技术员可调用相机拍照或从本地上传多张现场图片（如维护后清洁照片、零件更换对比图、仪器读数特写），系统自动打上时间戳与关联标记，作为工作完成的有力凭证。
  * 异常项联动：若勾选异常，必须填报异常现象描述与异常照片，用于自动联锁派生抢修。
* **验收标准**：技术员在现场维护单中能够编辑工单记录，成功上传工作完成照片并完成提交，详情页中高清展示工作完成证据图片。

#### REQ-MNT-008: 现场维护单异常联锁自动派生故障单
* **需求描述**：消除维护与抢修的断层，现场维护发现的异常自动接入抢修闭环。
* **处理逻辑**：
  * 技术员提交现场维护单时，系统在数据库原子事务中检查是否存在异常项。
  * 若存在任何异常项：
    1. 保存该现场维护单记录，标记为“维护发现异常”。
    2. 自动联锁生成一条处于“待处理”状态的故障抢修单。
    3. 自动将异常项填写的现象描述、拍摄的现场照片、关联设备、发生系统带入该故障单。
    4. 设备状态从“待维护”立即跃迁为“故障”。
    5. 触发即时邮件通知责任工程师。
* **验收标准**：现场维护单提交后，在故障管理列表中立即可见由该次维护自动衍生的高清带图故障单。

#### REQ-MNT-009: 维护超时判定与持续告警
* **需求描述**：对怠慢或遗漏的维护行为进行升级监控。
* **规则细则**：
  * 超过计划截止时间 3 天仍未完成维护打卡的任务，系统自动标记为超时未维护。
  * 每日向负责工程师及部门主管（管理员）发送催办邮件，并在仪表盘标红置顶展示。
* **验收标准**：超时任务在管理界面中以高亮红色警示条显示超期天数。

#### REQ-MNT-010: 多维度维护按时完成率统计分析
* **需求描述**：为管理层考核维保绩效提供数据支撑。
* **计算公式**：
  按时完成率 = (周期内按时完成维护任务数 / 周期内应完成维护任务总数) * 100%
* **统计维度**：支持按设备维度、按设备类型（PLC/风机等）、按责任工程师、按时间段（周/月/季度/年度）生成对比报表与柱状图。
* **验收标准**：报表能准确识别逾期提交与按时提交的数据并计算出精确到小数点后一位的百分比。

#### REQ-MNT-011: 维护历史记录查询与 Excel 导出
* **需求描述**：支持全量维护记录检索与归档导出。
* **验收标准**：支持按时间区间、设备、执行人组合查询，并能将完整巡检明细（包含各项检查结果）导出为 Excel 报表。

#### REQ-MNT-012: 基于实际累计运行工时的预测性维保与动态预警机制
* **需求描述**：针对非 7×24 小时连续运行的工业机台，提供操作员每日填报机台运行小时数能力，根据累计工时与计划周期（如 720 小时）动态触发提前预警通知（邮件）及维护工单生成。
* **验收标准**：
  1. 操作员每日可录入设备实际运行小时数，单日累计不能超过 24 小时。
  2. 当设备累计工时达到预警阈值（如提前 48 小时，即 672 小时）时，系统自动发送邮件提醒并创建待办维护工单。
  3. 当设备工时达到 720 小时周期阈值时，设备状态自动变为待维护。
  4. 技术员完成维护打卡后，工时计数器自动清零，进入下一轮周期。

### 2.4 故障管理与时效 (REQ-FLT)

#### REQ-FLT-001: 故障双渠道申报来源
* **需求描述**：系统全面覆盖两类故障上报场景。
* **场景定义**：
  * **来源一（巡检衍生）**：由巡检执行发现异常自动派生（REQ-MNT-008），草稿数据完备。
  * **来源二（突发主动报修）**：技术员或现场人员在日常巡视中发现设备突发故障，在系统中主动填报紧急报修单。
* **验收标准**：故障单列表中清晰标注来源标签（日常巡检异常 或 主动报修）。

#### REQ-FLT-002: 故障核心要素规范化录入
* **需求描述**：保证故障记录标准化，为后续知识库沉淀打下高质量数据基础。
* **必填要素**：
  * 故障标题与现象详细描述（如：“引风机启动后伴有金属摩擦剧烈异响，轴承外壳温升达85℃”）
  * 故障系统分类（电气系统 / 机械系统 / 气动液压系统 / 控制与网络系统 / 软件程序 / 其他）
  * 故障具体部件与位置（如：传动端轴承箱）
  * 故障严重级别：严重（停产停线）、一般（降效或旁路运行）、轻微（异响或表面损伤，暂不影响生产）
  * 关联设备（从设备库中选择）
  * 现场故障照片/短视频（至少 1 张清晰照片）
* **验收标准**：遗漏必填要素时系统阻止提交并给予明确错误提示。

#### REQ-FLT-003: 录入故障实时智能排查推荐 (核心特色)
* **需求描述**：在技术员录入故障现象时，系统实时从知识库中检索并主动推荐历史解决方案。
* **交互流程**：
  * 技术员在“故障描述”文本框中键入文字（如键入“风机 异响 温度高”）。
  * 前端采用防抖机制（300ms）调用后台相似度推荐引擎。
  * 页面右侧或浮窗实时滑出匹配度最高的前 3 条历史已解决故障案例，展示匹配百分比、历史根本原因及当时采纳的解决方案。
  * 技术员可点击直接查看完整历史案例，以便在工程师到场前自查或自愈。
* **验收标准**：输入典型故障关键词后，在 500ms 内即时展示相似历史案例推荐卡片。

#### REQ-FLT-004: 故障生命周期状态机流转
* **需求描述**：故障单全流程可闭环追溯，各阶段责任明确。
* **流转状态定义**：
  * **待处理 (Open)**：故障刚上报，等待工程师接手。
  * **处理中 (In Progress)**：工程师点击“接手处理”认领故障，状态变更，记录接单时间。
  * **已解决 (Resolved)**：维修完成后，工程师录入根本原因与处理步骤，状态变更为已解决，等待闭环验收。
  * **已关闭 (Closed)**：管理员或原报修技术员确认设备恢复正常运行后，执行“关闭归档”。
  * **重新打开 (Reopened)**：若在已解决后测试再次发现问题，可驳回重新流转至“处理中”。
* **验收标准**：各个状态转换时严格记录操作人、操作时间与流转备注。

#### REQ-FLT-005: 工程师故障接手与现场排查协同
* **需求描述**：支持工程师接单排查，并支持简单故障技术员自主快速维修标记。
* **规则细则**：
  * 简单故障（如：加润滑油、清理光电探头灰尘）：技术员参考历史推荐方案自行处置后，直接填报处理方法并由工程师线上复核确认。
  * 复杂故障：工程师接手，系统记录现场处理起止时间。
* **验收标准**：工单详情中完整展示责任人接手时间轴。

#### REQ-FLT-006: 维修结果、根因分析与成本消耗填报
* **需求描述**：维修完毕必须录入高质量复盘数据方可关闭。
* **填报内容**：
  * **必填项**：故障根本原因 (Root Cause)（如“润滑脂长期未更换导致轴承滚珠严重疲劳剥落”）。
  * **必填项**：详细处理方法与步骤（如“1. 拆卸防护罩；2. 使用液压拉拔器拆下旧轴承；3. 清洁轴颈；4. 热装新SKF 6205轴承；5. 加注耐高温润滑脂至2/3腔体”）。
  * **选填项**：更换的备件型号及消耗数量、维修后设备正常运行照片/参数读数截图。
  * **计量项**：停机影响时长（单位：分钟）。
* **验收标准**：工程师未填写“根本原因”或“处理方法”直接点击完成时，系统予以强拦截提示。

#### REQ-FLT-007: 标定“典型故障案例”
* **需求描述**：遴选出极具教学代表性与复发参考价值的高价值故障。
* **规则细则**：工程师或管理员可在故障处理完成或复盘时，勾选标记该记录为“典型故障案例 (Featured Case)”。
* **验收标准**：被标记为典型的案例在知识库中享有专属置顶徽章，并优先作为智能推荐候选，同时自动同步进入培训案例池。

#### REQ-FLT-008: SLA 服务级别时效监控与超时告警升级
* **需求描述**：对不同严重程度的故障设定严格的时间考核红线。
* **SLA 考核指标**：

| 故障级别 | 响应时效红线 (从上报到接手) | 解决时效红线 (从上报到解决) | 超时升级机制 |
|:---|:---:|:---:|:---|
| **严重 (Critical)** | <= 30 分钟 | <= 4 小时 | 超时每 30 分钟向主管发送紧急邮件并全屏标红 |
| **一般 (Major)** | <= 2 小时 | <= 24 小时 | 超时每 4 小时发送催办通知 |
| **轻微 (Minor)** | <= 8 小时 | <= 72 小时 | 每日汇总逾期通知 |

* **验收标准**：一旦响应或解决时长超过预设阈值，系统自动将工单标记为 SLA超时 并触发对应升级通知。

#### REQ-FLT-009: 故障综合查询与 Excel 导出
* **需求描述**：支持按时间跨度、设备类型、故障级别、处理状态、处理人等多条件组合筛选，并支持一键导出 Excel（包含根因与解决方案全文）。

### 2.5 历史维修知识库 (REQ-KB)

#### REQ-KB-001: 故障闭环自动沉淀机制
* **需求描述**：故障一旦完成闭环，其成果自动转化为知识资产，免去人工重复录入知识库的繁琐负担。
* **处理逻辑**：当故障单状态变更为已解决或已关闭时，后台异步事件总线触发知识入库流程，自动截取设备类型、故障现象、故障系统、根本原因、处理方法、现场图片形成知识条目。
* **验收标准**：故障单闭环后，知识库列表中即可检索到该条知识。

#### REQ-KB-002: 知识全文检索与中文分词索引
* **需求描述**：支持对知识库内容的高性能全文搜索。
* **检索范围**：设备名称、型号、故障描述、系统位置、根本原因、处理步骤、消耗备件。
* **分词与匹配**：后台建立分词倒排索引，支持多关键词模糊检索（如搜索“S7-1200 通信中断”）。
* **验收标准**：输入任意专业关键词，在 10000 条历史记录规模下，检索响应时间小于 1 秒。

#### REQ-KB-003: 知识库多维聚合筛选
* **需求描述**：除了文本搜索外，支持按工矿属性结构化精准钻取。
* **筛选维度**：设备类型、故障系统分类（电气/机械/自动化等）、故障严重等级、是否典型案例、沉淀时间范围。
* **验收标准**：勾选“变频器 + 电气系统 + 典型案例”，结果集精准过滤且支持即时排序。

#### REQ-KB-004: 相似度匹配推荐算法引擎
* **需求描述**：驱动 REQ-FLT-003 故障录入时的相似案例计算核心。
* **算法规格**：
  * 计算模型：结合文本 TF-IDF / BM25 算法与设备元数据加权（设备类型相同权重大幅提升、同一部件位置权重大幅提升）。
  * 评分输出：计算得出 0% ~ 100% 相似度得分。
  * 排序展示：过滤得分高于预设阈值（如 60%）的前 3~5 条记录，按得分倒序呈现。
* **验收标准**：当输入相同设备型号与相同故障词汇时，系统能以 >85% 的置信度排在首位推荐。

#### REQ-KB-005: 知识条目人工编校与标签管理
* **需求描述**：确保沉淀知识的准确性与权威性。
* **规则细则**：工程师和管理员具备对知识条目的编辑权限，可对自动沉淀的文本进行错别字修正、步骤优化，并可增加自定义标签（如 #轴承磨损、#2026汛期防潮专项）。
* **验收标准**：修改后记录保存修改人与版本更新时间，原始故障单数据保持客观留痕不变。

#### REQ-KB-006: 知识库数据批量导出
* **需求描述**：支持管理员和工程师将知识库条目导出为 Excel 格式，用于离线编制工厂维护手册。

### 2.8 系统支撑与配置 (REQ-SYS)

#### REQ-SYS-001: SMTP 邮件服务器集成与连通性自检
* **需求描述**：为系统通知引擎提供底层发信基础设施，必须提供**管理端可视化配置页面**，支持系统管理员在线维护发信服务器参数并持久化落库。
* **页面配置与持久化管理**：
  * 系统提供专门的“系统管理与参数配置中心”前端页面，允许管理员录入与修改 SMTP 服务器主机 (Host)、端口号 (Port)、发件人邮箱账号 (User)、授权认证密码/密钥 (Pass)、发件人显示昵称 (Sender Name) 及加密传输协议（SSL/TLS 与 STARTTLS 开关）。
  * 支持**动态热生效**：配置保存至数据库 `sys_smtp_configs`，后台定时调度引擎即刻读取最新配置发信，无需重启后端或重新部署容器。
  * **安全性与密码脱敏**：前端回显配置时密码字段强制脱敏为 `******`；保存配置时若密码字段为空或保持 `******`，系统自动继承并保留原有密码，避免误清空或明文泄露。
  * **合规审计记录**：每次页面修改并保存 SMTP 配置，系统均需自动向 180 天操作审计日志流水注入记录。
* **自检能力**：页面提供“发送自检测试邮件”交互能力，管理员配置完成后输入收件邮箱，系统支持传入已保存配置或当前表单草稿参数进行即时网络通信握手与发信自检，并友好返回成功或具体错误原因（如超时、账号密码认证失败）。
* **验收标准**：管理员在前端页面配置正确的 SMTP 参数并点击保存，数据库成功持久化；输入测试收件邮箱点击测试，5 秒内目标邮箱收到测试邮件；若配置错误参数时前台弹出精准错误提示。

#### REQ-SYS-002: 通知对象与工作组矩阵配置
* **需求描述**：支持对工厂不同班组进行分级通知路由。
* **规则细则**：管理员可按专业（如电气班组、机械班组）或物理区域配置邮件接收列表，并可指定单项维护计划由特定的工程师专人接收。
* **验收标准**：当电气设备故障上报时，邮件仅投递至电气组及对应工程师，避免邮件泛滥造成干扰。

#### REQ-SYS-003: 全生命周期事件驱动邮件触发策略
* **需求描述**：基于业务生命周期事件自动触发邮件投递。
* **触发矩阵**：
  * 维护到期提醒：按配置的提前天数（如 7天、3天、1天、当天）定时批处理投递。
  * 维护超时告警：超过 3 天未执行，每日清晨 8:00 投递催办邮件。
  * 故障突发上报：故障创建成功后立时投递给责任工程师。
  * SLA 超时破线：故障响应或解决逾期时，立即升级投递至主管管理员。
* **验收标准**：触发事件发生后，邮件异步放入投递队列，保障前台接口毫秒级返回。

#### REQ-SYS-004: 基础数据模板化 Excel 批量导入导出底座
* **需求描述**：构建统一的通用数据解析与序列化服务。
* **规则细则**：支持带下拉数据字典约束的标准 Excel 模板导出，导入支持流式解析与前端分步预览。

#### REQ-SYS-005: 180 天不可篡改全量系统审计日志
* **需求描述**：满足工厂工业安全合规要求与责任倒查。
* **记录范围**：对用户账户、设备台账、维护计划、故障流转、系统配置的所有新增、修改、删除动作记录全量日志。
* **日志字段**：日志ID、操作人姓名与ID、客户端 IP、操作模块、动作类型、请求URL、变动前后数据差异快照 (Diff)、操作时间戳。
* **安全约束**：审计日志保留至少 180 天，**系统不提供任何物理删除或篡改日志的前端入口与后端接口**。
* **验收标准**：管理员对某设备参数进行修改后，在审计日志模块能清晰比对出该设备原数值与新数值的 Diff 变化。

#### REQ-SYS-006: 工业附件与大文件存储管理
* **需求描述**：保障海量图纸、现场高分辨率照片与程序包的可靠存储。
* **规则细则**：支持文件本地磁盘存储或企业 S3 兼容对象存储，上传文件重命名为 UUID 规避重名覆盖，自动校验 MIME 类型，禁止任何可执行脚本（.sh, .exe, .bat, .php等）上传。
* **验收标准**：上传可执行后缀文件时，后端拒绝接收并报安全非法错误。

## 3. 非功能性需求规格 (Non-Functional Requirements)

### 3.1 安全性需求 (REQ-NFR-001)
1. **密码安全**：用户密码存储必须使用带盐哈希算法（bcrypt，cost >= 10）。
2. **防暴力破解**：同一账号或 IP 连续 5 次登录失败，锁定 15 分钟。
3. **会话安全**：基于 JWT 或安全 Cookie，客户端 30 分钟无操作自动使凭证失效。
4. **注入与跨站防御**：全系统严格使用参数化 SQL 查询，杜绝 SQL 注入；前端输入全局进行 HTML 转义，防御 XSS 攻击。
5. **横向与纵向越权防御**：所有数据操作接口均需在服务端校验当前用户的角色权限及关联工作类型的设备数据域。

### 3.2 性能需求 (REQ-NFR-002)
1. **首屏渲染性能**：首页仪表盘与关键列表页面在 100Mbps 局域网环境下，首屏完全渲染时间 < 3 秒。
2. **接口响应耗时**：
   * 95% 的标准 CRUD 业务接口响应时间 <= 300 ms。
   * 知识库全文检索与复杂多维筛选接口响应时间 <= 1000 ms。
   * 故障录入时的实时智能推荐防抖查询响应时间 <= 500 ms。
3. **列表分页标准**：所有数据列表默认分页大小为 20 条/页，单次最大允许拉取 100 条，杜绝无限制全表查询。

### 3.3 系统容量与扩展性 (REQ-NFR-003)
1. **资产与记录容量**：在无需数据库分库分表的前提下，系统底层性能必须稳定支撑：
   * 在线设备台账：>= 1,000 台
   * 累计历史故障记录：>= 10,000 条
   * 巡检维护记录：>= 50,000 条
   * 系统操作审计日志：>= 100,000 条（支持自动按 180 天滑动归档清理）
2. **并发能力**：满足工厂维护部门日常 50 人同时在线操作，现场维护单提交峰值支持并发 20 TPS。

### 3.4 可靠性与数据一致性 (REQ-NFR-004)
1. **软删除与历史保护**：设备、人员、维护计划等核心元数据采用软删除标记（is_deleted），严禁级联物理硬删除导致的历史业务孤儿记录与外键断裂。
2. **事务原子性**：巡检异常自动派发故障单必须在单一数据库事务内完成，任何一步失败全量回滚，杜绝“巡检显示异常但故障单丢失”的不一致状态。
3. **备份策略**：系统提供数据库定时备份机制，支持每日增量备份与每周全量冷备。

### 3.6 部署架构与现代 Linux 环境自适应 (REQ-NFR-006)
1. **双轨部署机制**：系统必须同时支持两种标准工业部署与运维模式：
   * **生产容器化编排 (Docker/Compose)**：支持一键编排、健康检查与隔离运行。
   * **Linux 原生敏捷部署 (Native Linux)**：适配无容器环境的标准 Linux 发行版（Ubuntu 20.04/22.04/24.04 LTS、Debian 12+、CentOS/RHEL 8/9）。
2. **PEP 668 环境自适应**：在现代化 Linux 环境（Python 3.12+ 外部受管环境）下，自动化安装部署脚本必须能够智能识别，自动构建 `.venv` 隔离虚拟环境安装依赖，彻底消除 `externally-managed-environment` 安装阻断。
3. **运维与生命周期管理工具**：提供 `deploy_linux.sh` 一体化运维脚本，支持 `install`、`start`、`stop`、`restart`、`status`、`test`、`docs` 等子命令，支持后台守护运行与即时健康探测。
4. **端口网络规划**：
   * 生产推荐：通过 Nginx 反向代理对外暴露单端口（80/443）。
   * 原生测试：前端（3000）与后端 API（8000）独立绑定，支持自定义指定端口运行。
